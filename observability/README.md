# Наблюдаемость Альфа-Курса

Стек запускается вместе с приложением: Prometheus собирает показатели Java-сервисов, Alloy отправляет журналы контейнеров в Loki, Grafana открывает четыре готовых дашборда. Отдельная установка компонентов не требуется.

## Запуск

Из каталога `documentation`:

```powershell
docker compose up -d --build
docker compose ps
```

Приложение откроется по адресу `http://localhost:8080`, Grafana — `http://localhost:3000`. Если порт занят, задайте `APP_PORT` или `GRAFANA_PORT` в локальном `.env` и повторите команду. Grafana доступна без входа только для чтения и опубликована на `127.0.0.1`. Prometheus и Loki доступны только внутри сети Compose.

При разработке из соседних локальных репозиториев укажите `*_SERVICE_BUILD=../<имя-папки>` и `FRONTEND_BUILD=../frontend` в `.env`. Для рекомендателя требуется точное имя локальной папки: `RECOMMENDATION_SERVICE_BUILD=../Recommedation-service`. Ключ Anthropic храните только в этом игнорируемом Git файле. Если ключ задан, открытие страницы рекомендаций может выполнить платный запрос к модели.

## Дашборды

| Дашборд | Адрес | Что показывает |
| --- | --- | --- |
| Состояние системы | `/d/alpha-system` | Доступность шести сервисов, запросы в секунду, долю 5xx, P95 времени ответа, память JVM и успех последнего опроса продуктовых метрик |
| Рекомендации и LLM | `/d/alpha-recommendation` | Число подборок, долю реально построенных LLM, причины перехода на baseline, задержку, кэш, вызовы и токены модели |
| События и A/B | `/d/alpha-product` | События из приложения, импорта и синтетики, воронку показ → клик → старт → завершение, CTR и возвраты по вариантам |
| Журналы сервисов | `/d/alpha-logs` | Ошибки и предупреждения, журнал рекомендателя и gateway |

Все адреса дашбордов открываются относительно `http://localhost:3000`. В Grafana раздел Explore позволяет выполнять запросы к источникам Prometheus и Loki. Для журналов выбранных сервисов используйте запрос `{service_name="recommendation-service"}` или замените имя сервиса.

## Как читать показатели

Сервис считается доступным, когда Prometheus получает ответ его `/actuator/prometheus` на внутреннем порту 8081. Метрики HTTP и JVM создаёт Actuator. Задержка P95 вычисляется из гистограммы HTTP-запросов за последние пять минут. Доля 5xx — скорость ответов 5xx, делённая на скорость всех ответов за те же пять минут. В первые минуты после запуска и при отсутствии запросов эти графики могут быть пустыми.

Сервис рекомендаций записывает исход каждой выдачи с метками `variant`, `engine` и `cache`. `variant` — назначенная A/B-группа; `engine` — движок, который реально сформировал ответ. При пустом каталоге, ошибке модели, невалидном ответе или отсутствии ключа фиксируется отдельная причина baseline. Время ответа измеряется для всего подбора, время LLM — только для вызова модели и разбора ответа. Токены учитываются, когда провайдер вернул сведения об их использовании. Идентификаторы пользователей и материалов не попадают в метки Prometheus.

Показатели `business_*` обновляются из базы `metric-service` каждые 30 секунд, поэтому включают импортированные события и переживают перезапуск приложения. `business_snapshot_success=0` означает, что последний опрос базы не удался; при этом предыдущий снимок остаётся видимым. CTR равен кликам, делённым на показы; доля стартов — стартам, делённым на показы; доля завершений — завершениям, делённым на старты; возвращаемость — пользователям с действиями более чем в один день, делённым на всех пользователей варианта. Нулевой знаменатель даёт 0. Метрики вариантов отражают только события с заполненным `variant`; импортированные события без варианта видны на графиках общего числа событий.

Панели рекомендаций заполняются после фактического запроса подборки. Для сравнения A/B задайте `AB_LLM_SHARE=50` в окружении рекомендательного сервиса и создайте действия пользователей в обеих группах. При значении по умолчанию `100` все пользователи относятся к группе LLM, даже если фактически получили baseline.

## Проверка

```powershell
docker compose ps
docker compose logs --tail=50 prometheus loki alloy grafana
docker compose exec prometheus wget -qO- http://localhost:9090/api/v1/targets
```

В ответе Prometheus у всех шести целей `job="application"` должно быть `health="up"`. В Grafana на дашборде журналов должны появиться сообщения после обращения к приложению. Конфигурационные файлы и JSON панелей лежат в `observability`. После изменения `generate-dashboards.mjs` выполните `node observability/generate-dashboards.mjs` и `docker compose restart grafana`. После изменения настроек Prometheus, Loki или Alloy перезапустите соответствующий сервис командой `docker compose restart <имя-сервиса>`.

Этот Compose предназначен для локального запуска и защиты проекта. Для публичного размещения Grafana и Loki нужны отдельные настройки аутентификации и сетевого доступа.
